# 2026-09-06：完成预览、FPS、当前帧保存与失败路径验证

## 背景

平均 FPS 显示已有逻辑验证，但缺少真实摄像头画面中的结果。当前帧保存也是尚未实现的项目目标。

## 实现

- 采集循环识别 S/s 按键，并使用 `cv2.imwrite()` 将当前帧保存到 `frames/`。
- 文件名使用当次运行中递增的序号，从 `frame0.jpg` 开始。
- 保存操作发生在 FPS 文字绘制之后，因此保存的画面也包含 FPS 信息。

## 验证

- 静态检查确认 S 和 s 都会进入保存分支。
- `frames/` 中已生成 `frame0.jpg` 至 `frame18.jpg`，全部被识别为 640×480、3 分量的 JPEG 图像。
- 实际解码查看了 `frame0.jpg`、`frame9.jpg`、`frame17.jpg` 和 `frame18.jpg`，文件可正常读取。
- 这些实际摄像头画面中可见 FPS 文字，且数值出现了 `29.9` 和 `30.0`，证明 FPS 信息已绘制到画面并随统计结果更新。
- 使用 `camera-detector` Conda 环境启动了程序；程序输出 `It's on!` 并持续运行，确认设备能打开且预览循环没有立即退出。
- 用户实际测试确认 Q/q 能正常退出，关闭窗口也能正常退出，两种路径都会释放摄像头资源。
- Conda 启动的程序最终以退出码 0 结束。
- 直接探测发现当前 OpenCV 后端会将索引 `-1` 解析为可用摄像头，因此它不适合用作无效索引。
- 改用索引 `9999` 后，真实的 `VideoCapture` 返回未打开状态。在可控测试中让 `main()` 获得该无效索引的 `Camera`，程序输出 `It's off!`、通过 `SystemExit` 退出并调用 `release()`。
- 使用可控 Camera 替身让第一次 `read_frame()` 返回 `(False, None)`，程序在一次读取后正常结束，并调用 `release()` 和 `destroyAllWindows()`。
- 失败路径的所有断言均通过，测试进程以退出码 0 结束。当前仍未将这些检查保存为仓库内的自动化测试。

## 已知限制

- `frames/` 目录需要预先存在。
- 序号在每次启动时从 0 重新开始，可能覆盖同名文件。
- 当前代码没有检查 `cv2.imwrite()` 的布尔返回值，因此写入失败时仍会输出保存成功的提示。
